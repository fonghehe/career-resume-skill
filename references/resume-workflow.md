# 根据履历生成简历

在用户要求求职简历、岗位版本或简历调整时读取。上游事实维护见 [career-workflow.md](career-workflow.md)。

## 读取和选择

复用用户指定的私人资料目录。读取 `references/career/README.md`、`profile.md`、`facts.md`、`project-index.md` 及相关项目卡，检查更正 / 排除记录。`output/career/career.md` 是便于阅读的聚合产物；与源记录不一致时先处理差异并重建，不把旧输出当新增事实。来源快照按需要读取，不要求重读所有附件或重新采集 Git。

资料为空但用户已提供经历时，先保存来源、任职和项目事实，建立最小履历；可以在同轮继续生成简历。没有任何经历时，只交付待填结构和必要问题，明确尚未形成可投递简历。局部润色 / 翻译复用已有条目，只处理指定范围，不强制重建完整库。

- 有 JD：拆出职责、技术、业务、交付与硬性条件，将每项对应到履历条目，区分直接相关、可迁移和缺口。
- 无 JD：使用用户指定方向或档案已有定位生成通用版，不编造公司要求。方向不明时，可先按已支持的经历生成通用版，在报告中说明假设。
- 只选 `confirmed` 或 `resume-supported` 的事实；后一种保留“旧简历支持”的来源状态，不称独立核实。确认只作用于明确字段，不能因一条确认升级整项目。
- `pending`、`proposed-to-verify`、`legacy-only`、`superseded`、`synthetic-draft`、`fabricated-excluded` 不进入真实简历正文；`git` 仅支持代码活动，不能单独升级职称、成果或上线责任。

## 编写和依据

通常从相关项目中选择最能支撑方向的案例，篇幅服从用户要求。每条写清本人动作、机制和已支持结果；没有结果数字就写具体功能或定性结果。个人项目单列，历史职称及任职日期保持真实，教育与联系信息未知时省略。

对每个实质性简历条目，在独立报告中记录：正文位置 / 内容、事实或项目条目 ID、来源 / 确认状态、采用范围及边界。概述和技能也要有对应证据；可合并重复映射，不能只给一个总括的“来自履历”。原记录缺 ID 时先分配稳定编号，不伪造出处。

JD 的关键词只改变选材和表达，不新增技术经验。英文保留参与程度；任职年限不能把重叠经历重复相加。正文不夹带事实 ID、证据状态、待确认项、匹配分数或内部备注。

## 交付和核对

保存 `output/resumes/YYYY-MM-DD-方向/resume.zh-CN.md` 或 `resume.en.md` 与 `match-report.md`。日期使用用户时区；旧版本保留，新版本加后缀。报告包含：通用版 / JD 目标、履历来源与版本信息、正文依据映射、项目选择与删减、能力缺口、必要问题及验证范围。没有 JD 时仍交付依据报告，明确没有公司 JD。

逐条核对公司 / 个人归属、日期、正式职称、责任程度、技术边界和指标。简历中的每个主张能回到履历条目；未采用的事实继续保留。Word / PDF 只在用户要求且实际工具可用时生成，并检查渲染与提取文本；Markdown 的一页 / 两页仅是篇幅目标。

生成简历后，新的用户确认先进入履历，再生成修订版。简历措辞本身不是新证据，不能反向写入履历升级事实。生成不包含外部投递、上传或发布。

## 面试材料与项目介绍

用户要求自我介绍、技术案例、面试准备或项目介绍时，复用相同的事实读取和状态规则，按请求选材，不要求先生成简历。用 `assets/templates/interview-template.md` 编写所需部分，保存到私人资料目录 `output/interviews/YYYY-MM-DD-方向/preparation.md`；局部请求仅处理指定范围，旧版本保留。

项目讲述覆盖背景、问题与约束、本人角色、动作与机制、方案取舍及有依据的结果和验证。讲述正文不夹带内部编号，文末单列主张到事实条目的映射和必要缺口。没有根因或验证记录时不编写“已定位 / 已验证”的故事；提出少量关键问题，允许先交付已有部分。

根据真实项目产生可能追问，并仅从已有事实回答。JD 中缺失技术可生成明确标注的通用学习 / 练习内容，不能冒充个人项目经验。新的用户陈述先进入履历，再修订材料；表达本身不成为新证据。
