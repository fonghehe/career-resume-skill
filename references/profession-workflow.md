# 按职业组织履历与个人网页

本 Skill 面向不同职业，不预设使用者是程序员。整理前复用用户的职业、经历与目标；职业不明时可先按已提供内容交付，不从技术模板反推职业身份。

## 从材料决定模块

职业名称是自由文本，不是枚举值；新增职业不需要注册、增加脚本或复制模板。先识别这次材料中的任职、学习、实践、能力和成果，再按用途选择展示方式：

| 已有材料 | 如何组织 |
|---|---|
| 任职、职责或长期服务 | 记录归属、本人角色、时间与工作范围；不要求拆成项目 |
| 作品、活动、专项工作或具体事件 | 需要详细叙述时建立可选案例，保留背景、动作、结果与来源 |
| 学历、培训、资格、研究、志愿服务等 | 在 `references/career/` 保存有来源的详细记录，按实际内容命名模块 |
| 转行或跨领域经历 | 保留原归属与职称，按本次目标说明可迁移经验，不改写历史职业身份 |
| 材料很少或职业尚不明确 | 先交付已支持的记录；没有的模块直接省略，不反问用户必须选一种职业 |

只有岗位或用户要求时才安排必要资格、作品或语言等模块；没有来源不填。简历不强制设置案例栏目，更没有案例数量下限。下面的职业场景仅帮助理解组织差异，未列出的职业按相同原则处理。

## 内容按事实，结构按职业

职业履历始终保留任职、教育、实践、成果及来源。公开网页只从用户允许展示的可用事实中组织模块，不把“简历精选案例数量”用于删掉履历。模块名称、顺序与条目可以调整，不要求每个职业使用项目、技术栈或仓库。

| 职业场景 | 可考虑的模块（有材料才生成） | 表达重点 |
|---|---|---|
| 销售 / 客户服务 | 客户服务范围、代表商机、解决方案、客户维护、资质 | 客户需求与约束、本人行动、跟进与交付结果 |
| 运营 / 市场 | 业务范围、活动案例、内容作品、渠道实践 | 目标人群、触达与协作问题、动作与有依据的结果 |
| 教育 / 培训 | 教学经历、课程设计、教研成果、教学作品、资格 | 学习目标、教学问题、实施与反馈，不编造提分数据 |
| 设计 / 内容 | 作品集、代表案例、研究与创作过程、展览或奖项 | 用户 / 创作问题、约束、方案与迭代依据 |
| 财务 / 行政 / 人力 | 业务流程、服务范围、专项实践、资格与培训 | 核对、协同、制度或流程问题及真实改进，不编造合规结论 |
| 医护 / 科研 | 专业经历、资格、研究或教学、脱敏实践 | 已支持的工作与研究贡献；无资格不补资格，不展示患者身份 |
| 工程 / 软件 / 数据 | 代表项目、工程实践、专业能力、作品、可选代码记录 | 业务问题与技术方案；只有实际代码资料才显示仓库与提交 |

这些是组织建议，不是固定模板。转行、自由职业或跨领域经历允许组合模块。数字、资格、奖项、客户关系和业务结果遵循[事实约定](fact-contract.md)；项目环境、团队成果与本人贡献仍分开。

## 网页数据与模块

继续使用 `local/data/timeline.json` 的通用任职 `career`、项目 / 案例 `projects`。没有仓库时 `repositories: []`、不填 Git 事件；页面不显示空的代码模块、导航、代码统计或零提交卡片。没有项目也可只展示职业模块，不初始化虚构项目凑版面。

可选 `presentation` 指定职业显示、主题、任职 / 案例标题、职业模块及顺序：

```json
{
  "profession": "教师",
  "theme": "sage",
  "technical": false,
  "careerTitle": "教学经历",
  "projectsTitle": "教学案例",
  "sections": [{
    "id": "courses",
    "title": "课程与教研",
    "items": [{
      "title": "课程名称（虚构格式示例）",
      "subtitle": "本人角色",
      "period": "保留原日期精度",
      "summary": "课程目标与有依据的工作",
      "bullets": ["具体动作与已支持结果"],
      "factIds": ["P01-A"]
    }]
  }],
  "order": ["career", "courses", "projects"]
}
```

这是 `presentation` 对象的格式示例，实际放入时间线顶层。模块可用于教育、作品、资格、研究、活动、服务案例等；`items` 为空时不展示。ID 使用唯一小写字母 / 数字 / 连字符；已有核心 ID `career/projects/repositories` 保留。`factIds` 对应源记录，不因放入网页变成新的确认。

网页风格按用户本轮要求选择。`theme` 支持 `sky`、`sage`、`lavender`、`sea`、`peach`，省略时使用 `sky`。主题作用于页首、浅色背景、栏目强调和交互元素。用户只要求改善布局时沿用已选主题，调整信息层级、阅读宽度、模块顺序与内容密度。页首保留身份与定位，任职按时间与职责组织，案例及教育、资格等模块在宽屏分栏、手机上单列。有作品或资格要求时可将对应模块前置，模块顺序写入 `order`。

根据个人履历生成网页时，通过自然语言选择配色，由智能体增量更新 `presentation.theme` 后重建网页，保留同一对象中的其他字段。用户未提出换色时沿用已有设置，首次生成且未指定时采用 `sky`，不要求用户编辑 JSON。个人网页和个人资料的工作台预览均不提供主题切换控件，分享页沿用生成时的配色。

只有 `meta.synthetic: true` 的虚构示例页提供「网页主题」即时试色，刷新后恢复示例配置。示例分享页保留当前试看的主题。不要为启用试色将真实个人资料标记为虚构。

没有代码证据且未声明 `technical: true` 时，案例详情默认使用“方法与工具 / 协作方式 / 业务与实践”，不强制前后端分类。软件等需要技术分类的页面可设 `technical: true`。旧数据不必迁移；已有代码记录继续保留。

职业模块按 `order` 调整，未列出的有内容模块继续显示。组织 / 年份筛选作用于任职与项目；其他职业模块展示完整资料。分享当前项目范围时不自动包含额外职业模块，需要单独选择其公开范围，避免把资格、教育或其他资料连带分享。

更新 Markdown 源记录在先，展示摘要在后，再构建并检查实际页面。不要把个人网页、简历、全文履历三个产物混成一个固定技术项目页。
