# 简历版式

生成完整中文简历或导出文档时读取。默认沿用用户提供的白底单栏参考样式；模块和内容根据本次描述、岗位与已有事实选择，不固定栏目数量或页数。此文件只规定排版，不提供个人经历。英文简历不套用本版式，改用[英文简历与国际版式](english-resume.md)的黑白 ATS 友好样式。

## 视觉规范

- A4 纵向、白底、单栏，无侧栏或照片。姓名左上方黑色加粗，约 22 pt；下方一行联系方式，仅放已提供信息。目标岗位按需放在头部，不强制占一行。
- 一级分节标题约 14 pt，使用所选主题的主色、浅色背景和左侧竖线；栏目之间留足间距。
- 正文约 10.5 pt、深灰色，中文无衬线字体搭配 Arial；正文固定行距约 16.8 pt（Word 中 `lineRule=exact` 且关闭文档网格），同类段落行距完全一致，避免出现一行松一行紧或字体替换后行距漂移。工作或项目名称加粗，角色与学历等次要信息常规字重，日期靠右。
- 使用简洁圆点列表；技能可按领域逐行写成“**类别：** 内容”。对已支持的核心业务、技术机制与结果少量加粗，不把整段变成粗体。
- 段落自然分页，标题跟随后续内容；不把整段任职 / 项目强制锁在同一页，不插入空行或手动分页来凑固定页数。实际字体与分页以渲染文件为准。

## 主题色选择

首次生成视觉版本时提供以下配色供用户选择；已有明确选择直接复用，不重复询问。主题未定不阻塞正文整理，可注明暂用晴空蓝预览，之后只换颜色、不重写事实或删减经历。配色只作用于标题、色条与浅色背景，正文保持深灰，优先保证打印和阅读对比度。所有色值以 `assets/themes/palette.json` 为唯一配置源，脚本直接读取六位 HEX，不根据颜色名称自行猜色；页面 #FFFFFF、姓名 #000000、正文 #333333、次要文字 #444444。

## 按内容选择模块

常见模块包括个人优势、教育经历、专业技能、工作经历、项目经历、开源 / 作品、证书或研究成果。它们是候选模块：根据用户描述、岗位重点、职业阶段与可用证据决定标题、顺序、合并或省略。教育重要时可前置，资深岗位可优先展示优势与工作 / 项目。不要因参考图有某栏就补造内容，缺少材料的栏整节省略。模块选择不等于删掉真实任职：完整经历版逐段覆盖；精简版的选材与省略规则见简历流程。

`assets/templates/resume-template.md` 是可调整的内容骨架，不是必须填写的表格。正文保留标准 Markdown：姓名用 `#`、模块用 `##`，任职 / 项目 / 教育条目可用 `###`。同一行信息以 `｜` 分隔，最后一段仅在有依据时写日期，例如：

```markdown
### 示例公司｜软件工程师｜2024.01–2025.12
### 示例大学｜本科 · 软件工程｜2018–2022
### 示例项目｜参与前端开发
```

以上为虚构格式示例。DOCX 导出将名称与补充信息分开排版，末尾日期使用右对齐制表位；没有日期时保留紧凑条目，不推断项目日期。保留 `**重点**`，超长名称允许自然换行，渲染后检查日期是否挤压。

Markdown 本身不携带色条和页宽。需要视觉成稿时用 `scripts/career.py export` 导出 DOCX；PDF 从导出的 DOCX 转换（如 Word 另存为 PDF），不要从 Markdown 用其他排版源重新转换，否则行距规范不会跟随。转换后逐页抽查：同类段落行距一致、日期未被挤压、无孤行标题。独立依据报告保留普通文档样式，不混入投递正文。引用截图只提取视觉特征，不把截图内的姓名、联系方式、公司、指标或开源数据写入公共模板，也不因样式参考自动采信其中经历。

## 导出脚本的两种版式

`--layout standard`（非 `.en.md` 文件的默认值）实现上述中文版式；`--layout international` 实现英文国际版式：US Letter 或 A4、0.75 in 边距、全篇 Arial、黑色全大写分节标题加底部细线、无主题色、正文统一 14.4 pt 精确行距。两版都逐样式写死 `lineRule=exact` 与 `snapToGrid=0`，不写 `docGrid`，也不在段落里覆盖行距，因此同类段落行距一致；切换版式不改变正文事实与文本顺序。国际版的完整参数、英文写作规则与 ATS 检查清单见[英文简历与国际版式](english-resume.md)。
