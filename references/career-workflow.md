# 职业履历生成与维护约定

从口述经历、旧简历、工作学习材料或已有档案建立文字履历，再用用户补充持续更新。无需先有求职目标；旧简历和代码仓库不是前置条件。事实字段、状态与更正规则统一见[事实约定](fact-contract.md)。

## 第一阶段交付

履历入口在 `local/references/career/README.md`，链接 `profile.md` 的完整任职 / 教育 / 技能记录、`facts.md` 的事实与确认、`project-index.md` 及项目卡、`sources.md` 和待确认问题。内容模板见 `assets/templates/career-kb-template.md`。按事实约定保留字段级记录，初版无需填满模板。

完成源记录后用 `scripts/career.py build` 聚合为 `local/output/career/career.md`，或由智能体按同一事实直接整理文字履历。工具读取当前 Markdown，不使用展示 JSON 中的合成日期改写任职，不解析附件或代写事实。聚合文件可重建，手工修改应写回对应源记录。没有文件工具时交付同等文本，明确尚未落盘。

聚合范围包括上述固定档案、`local/references/projects/` 下的项目卡，以及 `local/references/career/` 下的全部 Markdown 记录（含嵌套的技术案例、教育与能力记录）；履历入口只收录一次。补充案例后在履历入口或项目卡中建立链接，再重建文字履历。原始来源快照不自动拼入正文，仍通过来源索引追溯。

初版覆盖已提供材料即可，未知单列，不等待所有日期 / 指标确认。空档案只算初始化，不算个人履历完成。履历记录完整经历，不按岗位删减；HTML 是可选视图，不能代替文字履历。后续简历生成见 [resume-workflow.md](resume-workflow.md)。

## 简历与事实

保存实际可读来源和导入日期，按事实约定逐字段记录。档案、专业经历与可选案例记录放 `local/references/`，复用已有库，一次只问少量影响日期、归属、职级或职责的问题。

career 的 role 是正式职称，可选 level 是有来源的职级。相同 groupOrganization 合并同一公司，部门、时间与职级仍保留在内部阶段。职责不自动升级成职称；跨公司级别不能机械比较为晋升。

## 补充与字段更正

先读取履历入口、相关档案 / 项目卡及其事实和来源，不为局部补充重读全部附件。以源记录和最新明确确认为准；聚合履历与其冲突时重新生成，不能沿用旧产物中的职称、责任程度或数字。

一次更新按以下顺序完成：

1. 保存本次原话和日期为新来源，在来源索引中登记；旧快照保留原文。
2. 复用原条目 ID，更新对应档案 / 项目卡和 `facts.md`。每个变化写清字段、值、来源、状态；明确更正时注明取代的旧值，其他字段的值与状态保持原样。
3. 更新受影响的项目索引、履历入口和待确认项。不同文件引用同一事实时保持一致；尚待确认的指标仍保留待确认状态。
4. 运行 `python3 scripts/career.py build` 和 `python3 scripts/career.py validate`，检查实际文字履历。仅在用户要求时修订已有简历；新版本与报告一并另存。

如果用户更正或撤回了会影响简历的已采用事实，且已有简历版本，按[版本检查](resume-workflow.md#比较版本与检查过期主张)报告受影响条目；用户明确限定为只更新履历时，遵循本轮范围。需要同步已有网页或用户请求网页时，再按 [enhancements.md](enhancements.md) 合并展示摘要；展示工具的确认锁定和撤回只作用于 JSON，不能替代上述 Markdown 更新。

## 具体工作与可选案例

日常职责、教育、资格、服务、作品或研究可直接在档案或 `references/career/` 记录；不必先转换成项目。确需详细叙述的案例卡记录背景、本人职责、关键工作与结果。可选 milestones 保存 date、title、summary；日期保持来源精度，只有阶段标签时可留空。阶段根据真实变化归纳，不把每次提交写成一个项目故事。

完整横轴日期用于展示，只有月份时明确展示约定，原资料仍保留精度。任职区间不是项目区间，项目日期未知则两端留空，卡片保留。工作环境、团队成果与本人参与分别记录。

## 职业回顾与项目串联

用户想回顾多年工作、串联项目或总结经历时，先复用已有履历与项目卡，从记得清楚的具体事件补起，不要求 JD，也不默认生成求职简历。按已提供的时间、公司与项目归属组织经历；日期未知或项目并行时保留实际状态，不补造连续的成长时间线。

归纳各阶段本人做过的工作、反复处理的问题、实际职责变化和可迁移经验。每项归纳关联稳定事实 ID、项目卡或来源；仅有技术标签、工作年限、提交数量时，不推断能力等级、晋升、独立责任或业务成果。今天提出的改进建议与当年实际动作分开写，回顾中的解释不自动升级为 confirmed 事实。

按请求交付 `local/output/reviews/YYYY-MM-DD/review.md`，包含经历梳理、具体工作与变化、经验及依据、待确认项。由智能体基于源记录写作，`career.py build` 只聚合 Markdown。保留完整履历和旧回顾，日期目录已有文件时另用新文件名；无文件能力则在对话交付并注明未落盘。用户明确纠正事实时先更新源记录，再修订回顾；是否生成简历由本次请求决定。

### 月度或季度回顾

按用户时区把「本月」「上季度」转换为明确日期范围，报告写明起止日期。指定范围时按指定范围。优先读相关项目卡、阶段与来源，只使用材料支持的日期精度。区分范围内实际发生的工作、在本期补记的旧工作，以及无法判断是否发生在本期的记录。仅有提交日期时可列活动线索，不推断该期上线或成果。

保存为 `local/output/reviews/YYYY-MM-DD/period-review.md`，已有同名稿件则另存版本。按「本期本人工作与有依据的成果」「职责变化」「跨期或日期待确认」「待补证据」组织，附事实 ID 与来源；没有相关记录时交付缺口和一到三个具体补充问题。用户明确确认并要求写入的条目才按维护流程入库。可用[回顾教程](../docs/guide/review-career.md#按月或季度回顾)中的可复制指令。

## 可选代码证据

只有实际存在代码材料且本次请求需要时，另读 [维护与分享](enhancements.md) 中的本地 Git 流程。没有代码材料不创建仓库、统计或空代码栏目。

## 输出与公开边界

career.py build 聚合完整文字履历，career.py web 按需生成离线 HTML，career.py validate 检查结构和页面一致性。页面按事实和用途选择任职、案例、教育、资格或其他模块；只有实际代码资料才展示代码记录。确认问题保留在源档案，旧资料的附加字段不删除。

个人资料留在私人目录，公共 starter 为空，虚构网页演示在独立 `examples/career-demo/` 中设置 `meta.synthetic: true`，文字演示在 `examples/resume-demo/` 明确标注虚构。公开导出按受控空模板执行；原附件、代码仓库和 output 另行备份。
