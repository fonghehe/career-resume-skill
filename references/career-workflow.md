# 职业履历生成与维护约定

从口述经历、旧简历、项目说明或已有档案建立文字履历，再用用户补充及可选的本地 Git 证据持续更新。无需先有求职目标；旧简历和代码仓库不是前置条件。

## 第一阶段交付

履历入口在 `local/references/career/README.md`，链接 `profile.md` 的完整任职 / 教育 / 技能记录、`facts.md` 的事实与确认、`project-index.md` 及项目卡、`sources.md` 和待确认问题。内容模板见 `assets/templates/career-kb-template.md`。每个可引用事实保留稳定条目 ID、来源、状态和职责边界；字段有不同状态时分别记录，不整段升级。

完成源记录后用 `scripts/build_career.py` 聚合为 `local/output/career/career.md`，或由智能体按同一事实直接整理文字履历。工具读取当前 Markdown，不使用展示 JSON 中的合成日期改写任职，不解析附件或代写事实。聚合文件可重建，手工修改应写回对应源记录。没有文件工具时交付同等文本，明确尚未落盘。

聚合范围包括上述固定档案、`local/references/projects/` 下的项目卡，以及 `local/references/career/` 下的全部 Markdown 记录（含嵌套的技术案例、教育与能力记录）；履历入口只收录一次。补充案例后在履历入口或项目卡中建立链接，再重建文字履历。原始来源快照不自动拼入正文，仍通过来源索引追溯。

初版覆盖已提供材料即可，未知单列，不等待所有日期 / 指标确认。空档案只算初始化，不算个人履历完成。履历记录完整经历，不按岗位删减；HTML 是可选视图，不能代替文字履历。后续简历生成见 [resume-workflow.md](resume-workflow.md)。

## 简历与事实

保存实际可读来源和导入日期。原简历记 resume-supported；用户明确陈述或确认按对应字段记 confirmed，并保存原话与确认日期。文本 / 口述来源不伪造 PDF 哈希或页数。档案与项目卡放 local/references，已有库复用，未知可留空。一次只确认少量影响日期、归属、职级或职责的事实。

career 的 role 是正式职称，可选 level 是有来源的职级。相同 groupOrganization 合并同一公司，部门、时间与职级仍保留在内部阶段。职责不自动升级成职称；跨公司级别不能机械比较为晋升。

## 项目与阶段

项目卡记录背景、本人职责、关键工作与结果。可选 milestones 保存 date、title、summary；日期保持来源精度，只有阶段标签时可留空。阶段根据真实变化归纳，不把每次提交写成一个项目故事。

完整横轴日期用于展示，只有月份时明确展示约定，原资料仍保留精度。项目日期未知则两端留空，卡片保留。项目后端环境、团队成果与本人参与分别记录。

## 职业回顾与项目串联

用户想回顾多年工作、串联项目或总结经历时，先复用已有履历与项目卡，从记得清楚的具体事件补起，不要求 JD，也不默认生成求职简历。按已提供的时间、公司与项目归属组织经历；日期未知或项目并行时保留实际状态，不补造连续的成长时间线。

归纳各阶段本人做过的工作、反复处理的问题、实际职责变化和可迁移经验。每项归纳关联稳定事实 ID、项目卡或来源；仅有技术标签、工作年限、提交数量时，不推断能力等级、晋升、独立责任或业务成果。今天提出的改进建议与当年实际动作分开写，回顾中的解释不自动升级为 confirmed 事实。

按请求交付 `local/output/reviews/YYYY-MM-DD/review.md`，包含经历梳理、具体工作与变化、经验及依据、待确认项。由智能体基于源记录写作，`build_career.py` 只聚合 Markdown。保留完整履历和旧回顾，日期目录已有文件时另用新文件名；无文件能力则在对话交付并注明未落盘。用户明确纠正事实时先更新源记录，再修订回顾；是否生成简历由本次请求决定。

## 本地 Git

import_git_activity.py --folder /项目目录 --author-email 本人邮箱 读取多个仓库，--repo 读取单仓库。只读本地 refs，匹配完整本人邮箱，不 fetch、clone、切分支或提交。本人历史邮箱可重复提供。

repository 是活动区间与数量，records 保留完整 SHA、双日期、作者邮箱与主题，timelineEvents 是逐提交记录。文件夹 reports 保存各仓库及相对目录，skipped 列无法读取的仓库。无匹配保留空记录。

摘要放 repositories，事件放 gitEvents，以已有 projectId 关联；归属不明独立统计。更新按同仓库同 SHA 去重。项目 Commit 总数来自关联仓库摘要，不把只载入的部分明细当作总数，不混入其他作者。

Git 时间只描述代码活动，不证明入离职、上线、独立成果或贡献比例。原始主题保持原样，不补造情绪、根因或量化结果。

## 输出与公开边界

build_career.py 聚合完整文字履历，build_timeline.py 按需生成离线 HTML，validate.py 检查结构和页面一致性。页面展示公司职级、项目阶段与仓库统计，具体 Commit 按需展开；确认问题放档案中。旧资料的附加字段不删除，但生活片段不进入项目统计页。

个人资料留在私人目录，公共 starter 为空，虚构网页演示在独立 `assets/examples/career-demo/` 中设置 `meta.synthetic: true`，文字演示在 `assets/examples/resume-demo/` 明确标注虚构。公开导出按受控空模板执行；原附件、代码仓库和 output 另行备份。
