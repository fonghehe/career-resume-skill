# 事实记录与状态流转

整理履历、生成简历和维护展示时共用本约定。它约束现有 Markdown 记录；无需迁移资料库或另建一份事实 JSON。

## 最小记录

每条可引用事实保留以下信息；档案、项目卡和依据报告引用同一 ID，不复制成新的事实。

| 字段 | 记录约定 |
|---|---|
| ID | 复用稳定编号，如任职职称 `E01-T`、任职日期 `E01-D`、本人工作 `P01-A`；更正不重新编号 |
| 字段和值 | 写明归属、本人动作 / 程度或日期等具体字段；不同状态拆开记录，项目环境和团队结果单列 |
| 状态 | 使用下表；未知值留空，日期保留原精度，不补齐日、指标、职称或职级 |
| 来源 | 来源 ID、相对 `local/` 的路径及实际原话 / 摘录位置；文本口述不虚构页码或文件哈希 |
| 记录日期 | 区分本次记录 / 确认日期与经历发生日期 |
| 变更 | 更正时保留旧值、旧来源和取代关系；不改原始来源快照 |

示例（虚构）：`E01-T｜正式职称：软件工程师｜confirmed｜S2，references/sources/S2.md｜2026-10-23 本人更正，取代 S1 中的“前端工程师”`。同一任职的 `E01-D` 仍可保持 `resume-supported`。

## 状态与可采用范围

| 状态 | 含义与处理 |
|---|---|
| `confirmed` | 本人明确陈述或确认的对应字段，可用于正文；不代表外部独立核实 |
| `resume-supported` | 旧简历支持的对应字段，可用于正文，报告保留来源限制 |
| `pending` / `proposed-to-verify` | 信息未知、冲突待澄清或仅为待核实方案；保留问题，不进正文 |
| `legacy-only` | 仅有历史遗留表述，尚无适用来源，不进正文 |
| `superseded` | 已被明确更正取代的旧值，仅保留历史 |
| `fabricated-excluded` | 已排除的编造内容，不因润色或新输出恢复采用 |
| `synthetic-draft` | 公共虚构教学草稿，不进入真实履历 |

只有新增的本人明确陈述 / 确认才能把对应字段改为 `confirmed`；导入旧简历仅能支持 `resume-supported`。新材料与已确认字段冲突时保留原确认并询问；本人明确更正或撤回时记录变更，其他字段保持原值与状态。撤回后没有可用支持的字段转为 `pending`；明确否认的旧值保留在历史 / 排除记录中，不能回退采用。

`git` 是代码活动证据类型，不能自动升级任职、上线、成果或个人能力。`display-only` 是展示表达标记，不能替代以上事实状态。网页 `career-workbench-current` 字段块保存当前值与历史时，逐字段取当前值及对应来源，不能把旧表述或展示摘要当作本人新确认。展示 JSON 只是有范围限制的投影，不承担完整事实库职责。

工作台中未知或清空的事实字段保留空值并标为 `pending`，不保留该字段在展示摘要中的旧确认标记和旧支持来源；历史值、来源快照与修改记录继续保留。清空一个字段不改变其他字段的状态。

在用户授权的独立临时完整副本中做行为测试时，可按正常流程模拟 `confirmed`；状态仅在该测试内有效，所有文字产物标注虚构，展示数据设置 `meta.synthetic: true`，不回流真实履历。
