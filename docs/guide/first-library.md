# 先生成自己的履历

直接讲述经历，或提供旧简历和项目材料，先得到一份完整文字履历。后续补充、更正或生成不同方向的简历，都使用同一份记录。无需先填表、准备 JD 或提供代码仓库。

## 提供材料

首次使用先按[快速开始](quick-start.md)选择工作副本；本页说明第一份履历的材料与交付。用能读写文件的智能体打开完整项目。经历可以直接在对话中讲述；旧简历和原始附件可放 `local/private/`。基本工具需要 Python 3.9+；附件解析取决于宿主，不能读取时提供可读文字。

```text
请读取这个项目的 SKILL.md。
我的经历是【口述内容或实际材料路径】。
先整理任职时间、正式职位、教育、项目职责、技术和有依据的成果，
保存来源与待确认项，生成完整文字履历和可维护的资料入口。
未知先留空，不清楚的地方只问少量关键问题。
```

没有旧简历也可以开始。智能体保存口述来源和本人确认，不伪造附件哈希。只有明确要求网页或 Git 统计时，才需要展示数据、代码目录及本人署名范围。

## 第一阶段拿到什么

| 位置 | 内容 |
|---|---|
| `local/references/career/README.md` | 履历入口，链接实际维护的源记录 |
| `local/references/profile.md`、`facts.md` | 完整任职、教育、技能和事实状态、确认与更正 |
| `local/references/project-index.md`、`projects/` | 项目索引、稳定条目编号、本人职责、工作、成果及依据 |
| `local/references/sources.md`、`sources/` | 来源索引、实际读到的文字快照和导入记录 |
| `local/references/questions-to-confirm.md` | 尚未确认的关键事实 |
| `local/output/career/career.md` | 可直接阅读的完整文字履历，汇总上述记录 |

初版覆盖已提供材料即可；未提供的教育、联系方式或项目日期留空。空模板只算初始化，不能当作个人履历交付。履历保留完整经历与职责边界，不按岗位裁剪。

文字履历由智能体整理源记录后生成。手动聚合可以运行 `python3 scripts/build_career.py`；工具只聚合当前 Markdown，不提取附件或编造事实。后续修改源记录后重新生成，不在聚合文件中直接改事实。

## 补充事实就能更新

```text
2025 年我在同一家公司从 P5 调整到 P6，正式职称是高级前端工程师。
这个控制台我负责前端状态订阅，服务端由同事负责。
请保存这次确认，更新对应任职阶段和项目卡，再生成文字履历。
```

同一公司内的变化保留内部阶段；技术负责职责不自动等同于正式职称。智能体按字段更新，保留旧来源，遇到与已确认事实冲突的材料先说明。已有简历版本不会自动被覆盖。

## 第二阶段：根据履历生成简历

如果这次主要想总结多年工作，可先[回顾项目与经历](review-career.md)，把各阶段的工作和依据梳理清楚。下面的简历步骤按需进行。

```text
请根据最新履历生成前端方向的中文通用简历，目前没有公司 JD。
交付可直接使用的正文和独立依据报告，说明每条内容的事实依据、
项目选择与删减、能力缺口。不要为了篇幅改写完整履历。
```

提供 JD 可以生成岗位版。同一份履历可以产生多个简历版本，旧版本保留。详细提示、正文与报告的交付标准见[根据履历生成简历](generate-resume.md)。

## 按需添加网页与代码证据

需要可浏览的概览时生成 `local/showcase/project-timeline.html`，展示公司职级、项目阶段与本人 Commit 统计。项目代码由你指定目录，作者邮箱明确后才采集；提交日期不替代任职日期，Git 数量不推断职级或个人成果。

后续直接按[补充与更正履历](update-career.md)继续使用同一份档案。

[完整虚构示例](../example.md)展示文字履历、简历依据与项目页面；[网页生成](generate-webpage.md)、[Git 统计](git-timeline.md)和[命令参考](../reference/commands.md)提供可选工具细节。分享和备份见[隐私说明](privacy.md)。
