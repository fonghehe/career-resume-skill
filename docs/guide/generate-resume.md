# 根据履历生成简历

已有履历后，可以生成一份通用简历，也可以提供 JD 生成岗位版本。同一份履历能对应多个版本，完整任职与项目事实始终保留。

## 没有 JD：生成通用版

```text
请读取 SKILL.md，复用当前 local/ 中的最新履历。
根据我的前端开发经历生成中文通用简历，目前没有公司 JD。
请交付可直接使用的简历正文和独立的依据报告，说明选择了哪些事实、
省略了哪些经历以及还缺哪些信息。保留完整履历，别把缺少的数字补出来。
```

方向可以换成你的实际目标；没有指定方向时，智能体根据档案已有定位整理通用版，并说明假设。联系方式、教育或非必要字段缺少时可以省略，不必先填完所有信息。

## 有 JD：生成岗位版

```text
这是我要申请的岗位 JD：【粘贴岗位要求】。
请从现有履历选取最相关的任职、技能和项目，生成中文岗位简历。
报告中逐条对应正文与履历事实，并区分直接相关、可迁移和能力缺口。
项目环境不写成本人技能，没做过的技术不因为 JD 要求就补上。
```

智能体按职责、技术、业务场景和硬性要求选择事实。你参与的工作仍写成参与；个人项目独立展示；缺少指标时用具体功能或定性结果，不编造性能提升比例。

首次直接请求简历时，也可以一并提供经历。智能体先把已有材料保存成最小履历，再在同一轮生成可用版本，不需要重复输入。完全没有经历材料时只能先得到待填结构和必要问题。

## 两份交付分别是什么

| 文件 | 内容 |
|---|---|
| `local/output/resumes/YYYY-MM-DD-方向/resume.zh-CN.md` 或 `resume.en.md` | 可直接使用的正文：概述、技能、真实任职、精选项目与已提供的教育等 |
| 同目录 `match-report.md` | 目标与履历基线、正文事实依据、选材与删减原因、要求映射、缺口和验证范围 |

没有 JD 时，报告说明采用的通用方向，不伪造公司要求。报告中的稳定条目编号可回到事实记录和项目卡；简历正文不夹带内部来源编号、待确认项或匹配分数。

旧简历支持的事实可以采用，但保留其来源状态，不能称为已独立核实。待确认、推测、已撤回或被更正的事实不进入正文。Git 记录仅支持代码活动，不能单独证明职称、上线责任或业务结果。

## 检查与后续修改

检查公司归属、正式职称、任职日期、本人参与程度、技术边界和数字是否有依据。完整履历聚合文件与档案不一致时，先更新源记录并重新生成，避免沿用过期版本。

```text
我确认 P01-A 的职责是负责前端模块，服务端仍由同事负责。
请先保存这条确认，再基于最新履历生成简历的新版本，保留旧版本。
```

只需润色一条或翻译一段时，直接指定范围即可。英文保持原有职责程度，不自动加强为带领或架构负责。简历措辞不会反向变成新事实。

Word / PDF 按需生成；工具不可用时交付 Markdown，并说明实际格式。未渲染的 Markdown 只能以一页 / 两页为篇幅目标，不能声称已完成分页。生成简历不包含上传、发布或投递。

首次使用从[快速开始](quick-start.md)开始，已有履历更新见[补充与更正](update-career.md)；工具输入和边界见[命令参考](../reference/commands.md)。
