# 根据履历生成简历

已有履历后，可以生成一份通用简历，也可以提供 JD 生成岗位版本。同一份履历能对应多个版本，完整任职与项目事实始终保留。

## 版式固定，模块按需选择

默认采用白底单栏：姓名和联系方式置顶，分节标题配所选主题的主色、浅色底和左侧竖线，任职 / 项目名称加粗，日期靠右。正文适量加粗核心词，使用简洁列表和自然分页。

个人优势、教育、专业技能、工作、项目、开源 / 作品等都是候选模块；智能体根据本次描述、岗位重点和已有事实决定取舍与顺序，也可增加有依据的证书、研究成果等栏目。不会为了填满参考版式而编造内容或保留空模块，也不固定页数。

Markdown 保存内容结构；色条、页宽和日期右对齐由 DOCX 导出落实。完整视觉规范在公共 `references/resume-style.md`。提供参考截图时，仅提取排版，截图中的个人信息和经历不会自动进入你的事实库。英文简历改用黑白国际版式，见下节。

## 选择主题与经历范围

主题可以选晴空蓝、鼠尾草绿、雾紫、海盐青或杏桃橙；字体、单栏、日期对齐和模块排版保持一致。已有选择直接复用。命令行用 `python3 scripts/career.py export --list-themes` 查看，导出加 `--theme sky`、`sage`、`lavender`、`sea` 或 `peach`。

“完整经历版”逐段保留真实任职，项目核对覆盖后按信息量展开或简述，项目数量不设上限；“精简投递版”按岗位和篇幅选材，项目经历通常最多精选 3–4 个与岗位最相关的案例着重展开，省略项在依据报告说明。项目条目建议先写业务背景与难点（真实存在的业务或规模约束、协作 / 交付问题），再写你做了什么和有依据的结果；技术栈只列本人实际使用且与岗位相关的，不堆砌关键词。仅说“根据履历生成”时，不会自动只留最近两三家公司，也不会为了两页删掉早期经历。本轮明确要求优先于旧的精简偏好。

## 英文简历与国际版式

需要英文简历、海外投递或中英双语版本时，正文保存为 `resume.en.md`，并使用[英文简历与海外投递](english-resume.md)的规则：标准 ATS 分节标题、动词开头的短条目、`Mon YYYY – Present` 日期、不写照片与私人信息，公司 / 学校 / 项目译名未确认时在依据报告标注。

导出用国际版式，不用主题色：

```sh
python3 scripts/career.py export "…/resume.en.md" --layout international
python3 scripts/career.py export "…/resume.en.md" --layout international --page a4
```

默认 US Letter，英国 / 欧洲等 A4 地区加 `--page a4`。中文版式仍是默认值，`--theme` 只影响中文版。事实边界、项目精选与依据报告要求与中文版完全相同，翻译不会把参与写成主导或补造指标。

## 没有 JD：生成通用版

```text
请读取 SKILL.md，复用当前 local/ 中的最新履历。
根据我的前端开发经历生成中文通用简历，目前没有公司 JD。
请交付可直接使用的简历正文和独立的依据报告，说明选择了哪些事实、
覆盖了哪些任职和项目，以及还缺哪些信息。本轮采用完整经历版，保留每段真实任职，别把缺少的数字补出来。
```

方向可以换成你的实际目标；没有指定方向时，智能体根据档案已有定位整理通用版，并说明假设。联系方式、教育或非必要字段缺少时可以省略，不必先填完所有信息。

## 有 JD：生成岗位版

```text
这是我要申请的岗位 JD：【粘贴岗位要求】。
请从现有履历选取最相关的任职、技能和项目，生成中文岗位简历。
报告中逐条对应正文与履历事实，并区分直接相关、可迁移和能力缺口。
项目环境不写成本人技能，没做过的技术不因为 JD 要求就补上。
```

智能体按职责、技术、业务场景和硬性要求选择事实。你参与的工作仍写成参与；个人项目独立展示；缺少指标时用具体功能或定性结果，不编造性能提升比例。

首次直接请求简历时，也可以一并提供经历。智能体先把已有材料保存成最小履历，再在同一轮生成可用版本，不需要重复输入。完全没有经历材料时只能先得到待填结构和必要问题。

## 两份交付分别是什么

| 文件 | 内容 |
|---|---|
| `local/output/resumes/YYYY-MM-DD-方向/resume.zh-CN.md` 或 `resume.en.md` | 可直接使用的正文：概述、技能、真实任职、精选项目与已提供的教育等 |
| 同目录 `match-report.md` | 目标与履历基线、正文事实依据、选材与删减原因、要求映射、缺口和验证范围 |

没有 JD 时，报告说明采用的通用方向，不伪造公司要求。报告中的稳定条目编号可回到事实记录和项目卡；简历正文不夹带内部来源编号、待确认项或匹配分数。

旧简历支持的事实可以采用，但保留其来源状态，不能称为已独立核实。待确认、推测、已撤回或被更正的事实不进入正文。Git 记录仅支持代码活动，不能单独证明职称、上线责任或业务结果。

## 检查与后续修改

检查公司归属、正式职称、任职日期、本人参与程度、技术边界和数字是否有依据。完整履历聚合文件与档案不一致时，先更新源记录并重新生成，避免沿用过期版本。

```text
我确认 P01-A 的职责是负责前端模块，服务端仍由同事负责。
请先保存这条确认，再基于最新履历生成简历的新版本，保留旧版本。
```

只需润色一条或翻译一段时，直接指定范围即可。英文保持原有职责程度，不自动加强为带领或架构负责。简历措辞不会反向变成新事实。

## 导出可编辑的 Word 文件

对智能体说「把这份简历正文导出为 DOCX，并检查姓名、日期和排版」。如果已有 Markdown 正文，也可以把路径换成你的实际文件后运行：

```sh
python3 scripts/career.py export "local/output/resumes/2026-10-15-前端/resume.zh-CN.md"
```

同目录会出现 `resume.zh-CN.docx`，沿用上述版式并保留 `**重点**` 加粗。正文段落与列表使用同一固定行距（Word 中为精确 16.8 pt 并关闭文档网格），不会出现一行间距大、一行间距小。任职、项目或教育可写成 `### 名称｜角色或学历｜2024.01–2025.12`，末尾日期会靠右；未知日期省略。模块使用 `## 标题`，名称可按需要调整。用 Word 或其他兼容编辑器打开，确认字体、长名称换行、分页和联系方式。发现模板占位符会提示行号。PDF 从该 DOCX 转换（如 Word 另存为 PDF），不要用其他排版源重新转换；转换后逐页抽查行距一致、日期未被挤压、无孤行标题。

完整的自动版式、双格式导出和转换器说明见[导出中英文 Word / PDF](export-resume.md)。

## 同时看几个岗位

```text
这是岗位 A 的 JD：【粘贴原文】；这是岗位 B 的 JD：【粘贴原文】。
用同一份履历对照硬性条件、可直接支撑的经历、可迁移经验和缺口。
列出各自的原文和事实编号。先给我对比表，选定岗位后再生成简历。
```

结果在 `local/output/job-comparisons/YYYY-MM-DD/comparison.md`。例如同一段 React 工单经验可以直接支撑业务后台岗位，Java 接口联调只支持协作经历。

## 比较版本或检查旧简历

```text
对比【旧版本目录】和【新版本目录】的中文简历，说明用了哪些不同的事实。
另外检查我刚更正的 E01-T 是否被旧版本采用，列出需要复查的位置。
```

工具按依据报告中的事实编号定位旧主张。缺报告或映射不完整的版本需要人工核对。需要修订时，再请智能体基于最新履历另存新版本。终端用法见[命令参考](../reference/commands.md)。

首次使用从[快速开始](quick-start.md)开始，已有履历更新见[补充与更正](update-career.md)；工具输入和边界见[命令参考](../reference/commands.md)。
