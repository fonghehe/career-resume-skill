# 导入自己的简历，建立初始时间线

这一步只恢复简历中发生过什么。原简历可能不完整或过时，因此“简历中写过”与“本人最新确认”分开保存。

第一次使用还没有确定资料目录或调用方式时，先读[完整上手教程](first-library.md)。本页补充来源保存和字段确认的细节。

## 1. 提供来源

在支持附件的智能体中上传 PDF、Word 或文本简历，也可以把原文件放在 `local/private/imports/`，告诉智能体实际路径。文件解析由宿主完成；本仓库没有通用 PDF / Word 解析器。

原文件留在私人目录。公共文档、模板、Issue 和 PR 不接收真实简历。忽略规则不改变附件发送给宿主的行为，是否使用外部模型由你选择的客户端决定。

## 2. 使用这段提示词

```text
请按已读取的 career-resume-skill 规则整理我提供的简历。
先保存可追溯的文字快照与来源记录，不修改原简历。
按时间列出公司、部门/业务、正式职位、任职期间与项目归属。
先标记为 resume-supported；我本轮明确确认的内容才标 confirmed。
原文没有的日期、团队规模、个人职责、技术细节和成果标待补充。
分开记录正式 Title、实际职责、项目技术环境与我个人做过的部分。
建立 local/references/career/README.md 作为入口，链接档案、完整任职记录、
事实记录、项目索引、来源和待确认问题，列出实际保存的文件。
先交付完整文字履历和最多三个最重要的待确认问题。
暂时不要生成针对岗位的简历，也不要复制虚构示例作为我的经历。
```

## 3. 检查第一轮产物

| 位置 | 应该保存什么 |
|---|---|
| `local/references/career/README.md` | 链接到实际记录的知识库入口 |
| `local/output/career/career.md` | 可阅读的完整文字履历，保留日期原精度与事实状态 |
| `local/references/sources/S1.md` | 实际读到的来源文字快照 |
| `local/references/sources/manifest.json` | 唯一来源 ID、文件名、快照路径、导入日期 |
| `local/references/sources.md` | 来源用途与限制 |
| `local/references/profile.md` | 任职、职位、日期原精度及个人方向 |
| `local/references/facts.md` | 事实状态、职责边界与更正 |
| `local/references/projects/`、`local/references/project-index.md` | 初始项目卡与稳定编号 |
| `local/references/questions-to-confirm.md` | 尚需确认的问题 |

编号 `S1` 只是起点，已有来源时使用新的唯一 ID。读取到原文件才可计算它的 SHA-256；只收到文字时不要编造 PDF 哈希或页数。被截断、无法解析的段落记为待补充。

先建立能打开的履历入口和完整文字记录，再随着实际材料补充案例库、能力地图、证据库与成长记录。各视图链接来源和项目卡，避免保存多份互相冲突的事实；不为凑齐模板而创建没有内容的能力章节。

## 4. 本人逐条确认

重点检查入离职月份、项目属于哪家公司、正式职位是否准确，以及“负责 / 参与 / 带领”的程度。组织调整、转岗和空档期保留原样，不自动填平日期。

例如可以回复：

```text
E01 的入职月份正确，离职月份待查。
P01 是公司项目，我只负责前端内容页面，没有开发 Java 接口。
正式职位是前端开发，技术方案评审是职责，不是 Tech Lead 的正式 Title。
请保存这次确认，保留旧简历来源，并把冲突和待查项列出来。
```

最新确认进入事实库，旧来源仍保留。确认日期记录实际日期，不随意回填为项目发生时间。

## 5. 日期不够准确时

只有月份就保留月份。时间线 HTML 使用完整日期，智能体必须先向你确认展示约定，例如“月初表示开始、月末表示结束”；这个约定只服务于展示，不能变成精确入离职日期。未确认时先维护文字时间线。

未知项目日期可以暂不画区间，仍能保存项目卡。完整网页流程见[生成个人网页](generate-webpage.md)。

没有旧简历时直接口述经历即可建立履历，不需要先写一份简历再导入。
