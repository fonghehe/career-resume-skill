# 从项目文件夹统计本人 Commit

通常只需告诉智能体：“我的项目都在这个文件夹，看看 Git 记录，按项目统计我自己的提交。”它负责读取和组织，你不用逐个执行命令。

```text
我的项目在【实际路径】。请读取这些本地仓库的 Git 记录，
按项目整理代码时间线，保留原始提交，归纳有依据的项目阶段。
我在这些仓库使用的邮箱是【本人邮箱或几个历史邮箱】。
不清楚的项目归属问我一下，别把整仓库所有人的工作都算成我的。
```

若你没给邮箱，智能体可查看本地配置作为线索，只问一次必要的身份范围。Git 日期表示代码活动，不代替任职或项目上线日期。提交主题用于代码变更分类，项目归属、本人职责和成果由已有材料或本人补充支持。

## 页面里怎么看

“仓库与本人 Commit”先展示仓库活动区间，具体提交按需展开。可以按项目、仓库筛选，搜索提交主题，展开原始 SHA 与 Author / Committer Date。点进项目详情也能看到该项目的提交。

页面默认看仓库活动与数量，按需展开具体提交。项目关键阶段根据实际变更归纳，原始 feat/fix 主题保留。公开[示例](../example.md)用十四条虚构记录演示。

## 需要手动采集时

整个项目文件夹：

```sh
python3 scripts/import_git_activity.py --folder /path/to/projects --author-email you@example.test
```

单个仓库：

```sh
python3 scripts/import_git_activity.py --repo /path/to/repo --author-email you@example.test --project-id P01
```

路径、邮箱和项目 ID 换成自己的；历史邮箱重复 --author-email。--folder 递归寻找本地工作仓库，跳过 node_modules、构建目录和目录符号链接；同名仓库用相对目录区分。它不 fetch、clone、改分支或提交。

报告默认写入私人 output/git-activity。单仓库包含 repository（活动区间）、records（原始记录）、timelineEvents（逐提交事件）；文件夹报告用 reports 保存各仓库，skipped 列出无法读取的仓库。没有匹配就保留空记录，不虚构提交。

智能体把仓库摘要放入 local/data/timeline.json 的 repositories，把事件放入 gitEvents，并关联已有项目或先保留未关联状态；每次更新按同仓库同 SHA 去重，不覆盖原始报告。随后生成页面即可，不需要用户自己编辑 JSON。

整个仓库的次数不是各项目的独立成果，浅克隆、未拉取分支与缺少旧邮箱也会影响范围。PR 自动关联和托管平台同步尚未实现；当前只读已授权本地材料。

文件包含路径、邮箱与主题，保留在私人副本。见[隐私说明](privacy.md)。

## 目录归属与阶段证据

一个项目可以关联多个仓库，一个仓库可以按目录分为多个项目。告诉智能体目录归属即可，它会保存确认后的映射；同一 Commit 涉及多个项目时各项目可计入，仓库总数仍只计一次。

采集同时保留最近提交的修改文件、README 和版本标签。智能体根据实际变更提出少量阶段，待你确认，不能从 Commit 数或 tag 推断上线与个人成果。每月统计覆盖所有本人提交，模块统计会标明文件证据覆盖范围。
