# 补充、更正与维护履历

以后始终打开同一份工作副本。告诉智能体新事实或材料即可；它复用现有条目编号、来源和确认，不重新整理整份经历。

## 补充一个项目

```text
请读取 SKILL.md，继续使用现有 local/ 中的履历。
我补充 P01：我负责前端状态订阅、断线恢复和加载状态，
服务端由同事开发。目前没有性能提升数字。
请保存本次陈述与职责边界，更新对应项目卡和事实记录，
重新生成完整文字履历，列出剩余待确认事项。
```

不知道项目编号时直接说项目名称及归属公司，智能体先找到对应记录。已经明确的事实不反复问；缺少非必要字段可以继续交付。

## 更正一个字段

```text
我确认 P01 的归属应为个人项目，不属于前一家公司。
只更正归属，其他日期和职责状态保持原样。
请保留旧来源、记录这次更正，再更新文字履历。
```

本人明确更正只作用于对应字段。新材料与已有确认冲突时先保留已确认值，说明冲突并请求必要确认，不因“更新最近记录”而静默覆盖。

修改原始快照会丢失旧出处；应把新陈述另存来源，在事实记录中注明取代关系。待确认和被排除的内容继续保留相应状态，不能直接进入简历。

## 更新之后看哪里

事实先更新到 `local/references/` 的档案、事实记录、项目卡和来源索引，再聚合到 `local/output/career/career.md`。可手动运行：

```sh
python3 scripts/build_career.py
python3 scripts/validate.py
```

网页已经使用时，同步必要展示摘要后运行 `python3 scripts/build_timeline.py`，再校验。校验可能提示旧网页过期，修正源数据并重建即可，不能从旧网页倒灌事实。

## 让简历跟着更新

```text
请根据最新履历重新生成前端方向的中文简历。
保留上一版正文和报告，新版本说明这次采用的事实依据。
```

已有简历默认不被自动修改；只在你要求时生成修订版。新确认先进入履历，简历中的写作措辞不会变成新事实。详细标准见[生成简历](generate-resume.md)。

## Git、撤回与备份

需要更新代码证据时提供授权项目目录和本人署名范围，工具只读取本地记录，归属不明先独立保留。操作见[Git 统计](git-timeline.md)。

`update_profile.py` 的更新历史与撤回只覆盖展示 JSON，不包含另行修改的 Markdown 和原始附件。撤回整个事实更新需要对应源记录备份，不能只撤回 JSON 后认为履历也恢复了。

升级、迁移或准备分享前备份完整 `local/`；结构化私人 ZIP 只包含选定记录，不包含全部原件和简历产物。分享范围由你选择，见[隐私与备份](privacy.md)。
