# 回顾这些年做过的项目

做过不少项目，留下来的记录却可能只有旧简历上的几行字。可以用这份 Skill 逐个恢复项目背景、本人职责、关键问题和技术判断，再把它们放回完整经历中。暂时没有求职目标也可以开始，简历按需要再生成。

## 从一个记得清楚的项目开始

先按[快速开始](quick-start.md)准备完整个人工作副本，或让智能体读取该副本的 `SKILL.md`。把手头有权使用的旧简历、项目说明和附件放在 `local/private/`，回忆也可以直接在对话里讲述。

第一轮不用列完全部项目，可以先讲清楚一个具体事件：哪个页面或模块由你负责，当时出了什么问题，你采取过什么办法。没有材料支持的日期和结果先留空。

```text
我想回顾这些年做过的项目，目前没有求职目标。
请读取当前工作副本的 SKILL.md 和已有资料。
先从【项目名称】开始，我还记得的事情是：【回忆或材料路径】。
整理背景、本人职责、具体工作、问题和方案取舍，保存来源。
每轮只问少量关键问题，想不起来的先保留待确认。
先交付完整文字履历，暂时不生成简历。
```

公司项目、个人项目和开源贡献分别保留归属。项目整体技术环境、团队完成的结果与本人工作分开记录，避免多年之后把几段经历混成一个项目。

## 把项目串起来

整理好几个项目后，再看它们之间的联系：不同阶段主要负责什么，反复处理过哪些问题，责任范围有哪些实际变化。

```text
请根据已有履历做一次职业回顾。
按有依据的时间、公司或项目归属梳理经历；缺失日期单独保留。
整理各阶段的具体工作、反复处理的问题、职责变化与可迁移经验。
每项归纳列出对应事实编号、项目卡或来源，证据不足的标为待确认。
先生成回顾文件，不按 JD 删项目，也不生成简历。
```

串联依靠已记录的事实。例如，几个项目都有断线恢复问题，可以回看本人各次处理方式；若记录显示从开发页面逐步承担公共组件维护，可以描述这项具体职责变化。不能仅凭任职年限、项目数量或技术标签推断能力等级、晋升和成果。

“当时实际怎样做”与“现在重新做会怎样改进”分别记录。后者是今天的复盘意见，不应回写成当年的工作。

## 得到什么

| 文件 | 内容 |
|---|---|
| `local/references/career/README.md` | 可维护的源记录入口，找到事实、项目卡与来源 |
| `local/output/career/career.md` | 完整文字履历，保留已提供的经历与缺口 |
| `local/output/reviews/YYYY-MM-DD/review.md` | 按请求生成的职业回顾：经历顺序、工作变化、经验归纳、依据和待确认问题 |

回顾由智能体读取事实后写作，`build_career.py` 只聚合维护好的记录，不会自动分析跨项目经验。回顾与履历分开保存；源记录保持完整，已有回顾不覆盖，必要时在日期目录下用新文件名保存修订版。

## 回头检查的几件事

- **本人工作是否具体。** 能否说清做过什么，避免只剩“参与开发”“负责优化”。
- **归纳是否有依据。** 一项经验能否回到具体项目，职责变化能否找到相应记录。
- **哪些地方还模糊。** 列出缺失的归属、日期、技术判断或结果，下一轮选一项补充即可。

没有量化结果时，记录能说明的定性事实。想不起来的内容留在待确认区，不为让经历连贯而补故事。有些项目资料少，只写几句话也可以。

## 有旧仓库时补线索

提供自己有权访问的本地目录和提交邮箱，可以从本人 Git 记录里找回一些改动线索。先关联项目，再结合材料或本人确认补充背景。提交日期与数量不证明任职、上线责任或业务结果，具体操作见[本地 Git 证据](git-timeline.md)。

无权访问、已经丢失或包含不宜提供内容的仓库不必上传。口述和旧简历同样可以作为起点；向智能体提供材料前，按所在组织和所用客户端的要求处理内部信息。

后续想起细节，继续[补充与更正](update-career.md)。需要求职时，再[根据履历生成简历](generate-resume.md)或[准备面试材料](prepare-interview.md)。
