# 多智能体集成与兼容范围

## 三种入口

| 方式 | 怎么开始 | 能力要求 |
|---|---|---|
| 文件读取（通用入口） | 获取完整目录，让智能体读取其绝对路径下的 `SKILL.md` | 读写文件；执行脚本需终端能力 |
| 原生 Skill | 按所用客户端的安装机制导入完整目录，使用名称 `career-resume-skill` | 客户端支持本地 Skill；发现和调用机制各不相同 |
| 仅聊天 | 提供入口规则、相关模板和自己的文本，手动保存结果 | 不能声称自动保存资料或运行脚本 |

接入以能力为准：生态安装器选择多个智能体，通用 Python 工具导出任意技能目录或 ZIP，文件读取作为基础入口。`--agent` 内置名称只是快捷方式，不是支持范围上限；新增宿主可直接提供 `--skills-dir`。具体操作见[多智能体安装与调用](../guide/using-skill.md)。工具验证了目录、空模板、导出与拒绝覆盖行为，尚未逐一实测各客户端的原生发现、模型执行和附件能力，不以格式兼容替代运行验收。

## 统一格式与宿主差异

`SKILL.md` 的 `name`、`description` 与 Markdown 正文是通用入口；`references/`、`scripts/` 和 `assets/` 是可按需读取的资源。`agents/openai.yaml` 是可选的 OpenAI 展示元信息，其他宿主无需解释它即可读取公共入口。格式依据见 [Agent Skills 规范](https://agentskills.io/specification)。

本项目不在入口中硬编码宿主工具名或调用符号。目录扫描、显式调用、权限、附件与运行环境由客户端决定；`.agents/skills/` 是部分宿主支持的发现位置，不是“任何智能体自动支持”的保证。插件市场元信息、MCP 接口和账号导入仍需按目标平台配置。

## 自建与云端智能体

自建 Agent 可以将干净公开包挂载到沙箱或提供资源读取工具，分三层加载：

1. 会话中提供技能的名称、描述和入口位置，供模型判断是否适用。
2. 选中技能后读取 `SKILL.md`，随后只读取当前任务需要的规则、模板与资源。
3. 通过宿主的文件读写与终端工具执行，显式指定个人工作副本；没有终端时由模型整理 Markdown，不宣称执行 Python。

云端只能访问实际上传或挂载的资源，不能读取用户机器上的路径。公开技能与私人履历按授权分别挂载，后者不是公共技能包的一部分；需要持久化时由宿主保存资料，不能把一次性沙箱当成永久履历库。参考 [Agent Skills 客户端集成指南](https://agentskills.io/client-implementation/adding-skills-support)。本仓库不实现通用 SDK、MCP 服务器或跨设备资料同步。

没有原生发现功能但支持项目规则或快捷指令的宿主，可使用 `assets/templates/agent-entry-template.md`，填写入口与工作副本路径。入口仅负责路由，完整规则保持在原 Skill 中，避免多份正文逐渐不同步。

## 验证状态

| 层次 | 当前证据 | 不能据此声称 |
|---|---|---|
| 公共格式与资源 | 入口及相对链接校验、完整公开导出 | 所有宿主均能发现技能 |
| Python 安装 | 任意目录、通用 ZIP、共享项目目录、常见快捷方式及保护行为测试 | 目标客户端已经调用成功 |
| 生态 CLI | 按其维护者文档提供操作方式 | 本项目已执行外部批量安装或实测其全部客户端 |
| 模型与文档能力 | 提供人工行为验收场景 | 附件、表达、ATS、Word / PDF 排版已验收 |

## 共享安装与私人工作目录

每个用户或资料集使用独立工作目录。若手头的目录是自己的 clone，可直接在其中初始化；若它是共享安装、只读安装或为多个用户服务，则从安装副本创建新的完整工作副本：

```sh
python3 /path/to/installed/career-resume-skill/scripts/init_profile.py --workspace /path/to/new/my-career
```

源路径和目标路径换成实际位置；目标必须不存在。该命令复制公共规则、脚本和空档案，不迁移安装副本中任何人的个人资料，也不建立符号链接。新目录含自己的 `SKILL.md` 与工具，可以单独运行。随后在该目录执行 `python3 scripts/doctor.py`，告诉智能体所有读写和工具调用以该工作目录为准。

普通 `python3 scripts/init_profile.py` 只补当前副本缺少的文件；显式位置参数必须指向另一份**完整副本**，不是仅有数据的空文件夹。

## 环境与验证状态

| 能力 | 依赖 | 验证边界 |
|---|---|---|
| 初始化、校验、导出、HTML 构建 | Python 3.9+ 标准库 | 单元测试与离线完整导出检查 |
| Git 活动与回归测试 | 系统 Git | 临时本地仓库测试；不代表远端历史完整 |
| 教程站开发 | Node.js 22+、packageManager 锁定的 pnpm | VitePress 构建，独立于个人 HTML |
| 简历附件提取 | 宿主的文本/PDF/Word/OCR 能力 | 需要在目标客户端用虚构文件验收 |
| 推理、追问、简历表达 | 所选模型和宿主 | 需要行为验收，Python 测试不覆盖 |
| Word/PDF 成品 | 宿主文档工具 | 实际导出与分页检查后才能声称完成 |

CI 配置覆盖 Ubuntu 上 Python 3.9 / 3.14，以及 macOS 上 Python 3.14；配置不等于云端已经运行成功。Windows 基础命令可使用 `python` 或 `py -3`，尚不声明完整套件实测兼容，尤其符号链接测试可能依赖系统权限。

## 在自己的客户端验收

1. 让智能体读取入口，确认它使用的 Skill 路径和个人工作目录。
2. 使用虚构输入 `assets/examples/resume-demo/request.md`，明确这是教学演示；结果写入临时工作目录。
3. 检查 Java 等项目环境没有被写成本人能力，缺失指标没有被填补。
4. 让它列出读过的来源和写入文件；检查实际文件存在，公开空模板保持为空。
5. 如需附件、Word/PDF 或原生发现，分别验证后记录客户端、模型、日期及局限。

详见[行为测试](../maintainers/behavior-testing.md)。纯结构通过时，仅声明工具可运行，不声明模型表达或附件兼容已验收。
