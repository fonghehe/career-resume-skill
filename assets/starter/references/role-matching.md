# 岗位匹配与项目选择

从 facts.md 与 project-index.md 挑选允许使用的条目。把 JD 拆成业务、技术、职责、交付形态及硬性要求。

没有 JD 时按用户方向或档案定位生成通用版，说明假设，不制造公司要求。不从旧简历输出或展示页反向推断新事实。

- 直接相关：有本人贡献证据支持相同技术或机制。
- 可迁移：真实能力相邻，保持原领域与职责，不写成做过目标领域。
- 缺口：没有证据，放入报告，不写进简历。

通常选择 2–3 个相关项目，每项 3–5 条；篇幅随用户要求调整。近期与直接相关经历优先，但不用日期代替贡献证据。技术定位来自使用者档案，不统一指定语言或主身份。

证据映射包括 JD 要求、项目 / 条目 ID、状态、正文选择及缺口。没有量化数据时使用定性描述，不输出虚假 ATS 通过率或录用概率。
