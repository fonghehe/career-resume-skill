# 我的职业资料工作区

个人经历和产物都保存在本目录，公共规则位于上一级的 `SKILL.md` 与 `references/`。本文件只说明目录用途；尚未录入经历时，空模板不代表履历已经完成。

## 平时从哪里开始

- 阅读和维护：[职业履历入口](references/career/README.md)。
- 提供材料：原始简历、项目说明或附件放 `private/`；也可以直接向智能体口述。
- 查看产物：完整文字履历在 `output/career/career.md`，简历版本在 `output/resumes/`，离线网页按需放 `showcase/`。这些文件在生成后才出现。

## 直接告诉智能体

```text
请读取工作副本根目录的 SKILL.md，复用当前 local/ 中的资料。
先检查已有事实，然后根据我提供的新材料更新履历。
保留确认、来源与职责边界，重新生成完整文字履历。
```

需要简历时再说：“根据最新履历生成【方向 / 岗位】的【语言】简历，交付正文与独立依据报告，并保留旧版本。”

## 哪些文件能直接改

`references/` 是事实、项目卡、来源与个人写作设置；事实修改先保存在这里。`data/` 是可选网页展示摘要。`output/` 与 `showcase/` 是生成产物，不能把精修措辞反向当作新证据。

从完整工作副本根目录执行 `python3 scripts/build_career.py` 重建文字履历，执行 `python3 scripts/validate.py` 检查结构。重复初始化只补缺失文件；已有资料不被空模板覆盖。

原始附件、事实和产物默认不提交 Git。升级前备份整个本目录；结构化私人 ZIP 不包含全部附件与简历产物。
