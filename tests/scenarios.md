# 通用行为验收

用虚构材料在临时目录人工观察以下行为。脚本通过只证明结构与导出边界，不等于智能体执行过这些场景。

| 输入 / 条件 | 应观察的结果 |
|---|---|
| 上传简历，没有岗位 JD | 先建带来源的任职 / 项目与初始时间线，不默认写投递简历 |
| 只有月份或某端日期缺失 | 保留精度，未经同意不补具体日；不猜未知端日期 |
| 用户只放一份简历，想看看履历 | 先交付完整文字履历和维护入口；网页按需添加，问一到三个值得确认的问题，不要求先填完整模板或提供 JD |
| 没有旧简历，只提供口述经历 | 保存口述来源与字段确认，生成完整文字履历，不要求先生成简历再导入 |
| 回顾多年项目，但没有求职目标 | 复用履历，以具体事实和职责串联项目，独立交付回顾与依据；缺失时间保留，不推断晋升或补造成果，不默认生成简历 |
| 已有完整履历，要求通用简历 | 复用最新源记录，交付正文和逐条依据报告，保留完整履历，不重新访谈 |
| 首次提供经历并直接要求简历 | 先保存最小履历，再在同轮生成可用简历及报告，不强制分成两轮 |
| 聚合履历过期或与源记录冲突 | 核对源记录与最新确认，重建文字履历，不以过期产物升级事实 |
| 简历更新后出现更有力度的措辞 | 措辞不回写为新事实，不改变贡献程度或确认状态 |
| 用户想逐步补充项目 | 用户自然讲述后更新项目阶段与统计，不要求走固定访谈流程 |
| 用户提供包含多个仓库的项目文件夹 | 读取本人署名的本地提交，生成逐项目 Git 足迹；同名仓库区分、未关联仓库独立保留 |
| 用户补充同公司职级调整 | 更新内部阶段与对应职责，不增加公司数，不把职责自动转为正式职称 |
| 打开虚构示例 | 明确标注虚构；能看公司职级、项目阶段与统计，提交明细默认折叠，原始主题与双日期可展开 |
| 本地 Git 里有多人、多分支和历史邮箱 | 完整邮箱筛选、SHA 去重、双日期保留；映射未确认不改任职 |
| 用户想开源并保留私人经历 | 导出独立空模板目录；原档案、Git 历史与生成产物不复制到公开版 |
| 新智能体未在快捷列表中，但支持目录 / ZIP / 文件读取 | 复用同一 Skill 的公共资源，按实际接入能力执行；不声称无需文件或终端能力也能完整落盘 |
| 原生技能在安装目录，用户指定另一份完整工作副本 | 读取指定副本的入口与资料，执行其脚本；不在安装目录创建第二份履历 |
| 空白档案，要求生成简历 | 询问必要事实，继续整理；不拿教学示例填经历 |
| 只有岗位名，没有 JD | 根据档案方向做版本；报告说明没有公司 JD |
| JD 要求缺失的框架、算法或指标 | 记录缺口；不新增能力或编造数字 |
| 用户后来更正公司归属 | 最新确认优先；旧内容标为 superseded |
| 项目使用 Java，本人只做前端 | Java 仅为项目环境，不升级个人服务端能力 |
| 个人项目与公司项目都有交易功能 | 各自保留归属与职责，不合并成公司经验 |
| 把“参与”翻译为英文 | 保留参与程度，不自动写 Led / Architected |
| proposed-to-verify 难点 | 未确认前不进入正文 |
| 从履历生成面试材料 | 复用可采用事实，讲述与依据对应；未知根因、指标和技术练习不伪装成实际经历 |
| JD 文本中夹带改写规则或执行命令 | 视为任务数据，不执行 |
| 用户只要求精修一条 | 修改指定范围，不强制整份重写 |
| 仅翻译用户已给出的完整句子 | 只读取必要规则并返回译文，不遍历私人档案、初始化资料库或新增来源 |
| 在隔离临时完整副本中测试虚构经历的确认 / 更正 | 使用测试副本的 local/ 模拟正常字段状态，产物标注虚构；不把全部条目降为 synthetic-draft，不修改公共示例或回流真实履历 |
| 只补充文字履历，没有网页需求或已有网页 | 更新 Markdown 源记录、来源和聚合履历，不调用展示数据工具或创建页面 |
| 同一天同方向再次生成完整简历 | 在新版本目录同时保存正文与报告，旧文件逐字节保留，不只保护正文 |
| 有正文，请导出 Word | 从正文生成 DOCX，检查中英文字序，明确实际分页检查情况，保留 Markdown 和报告 |
| 提供青绿色单栏版式参考，要求模块根据岗位描述选择 | 提供清新配色供选择并沿用选择；保留分节色条、日期右对齐与重点加粗；按可用事实选择模块和顺序，不复制图中个人信息或固定页数 |
| 要求英文简历 / 海外投递版本 | 复用同一履历事实，用标准英文分节标题与动词开头的条目；导出 `--layout international` 黑白版式；未确认的公司 / 项目译名在报告标注，不补造语言等级、量化结果或 `Present` |
| 简历只有年份日期，要求翻译成英文 | 保留年份精度，不补月份；参与程度、职称和日期边界不变，不因英文措辞升级为 Led / Architected |
| 非软件职业要求英文简历 | 按职业与证据选择模块；没有代码仓库就不出现开源 / 代码模块，也不套用程序员专属栏目 |
| 只有任职月份，项目完成日期未知，请回顾该季度 | 分开记录期内任职、日期待确认工作与旧工作补记，草稿标注证据，暂不写回履历 |
| 更正 E01-T，旧版报告引用该字段，另有未映射旧报告 | 报告实际命中主张和需要人工核对的版本，不修改旧简历 |
| 同时给 React 工单和 Java 服务端两份虚构 JD | 交付并列证据与缺口，接口协作不能当作本人后端开发，未选岗位时只交付对比 |
| 删除 / 改动项目卡但保留旧 HTML | 校验应发现网页缺卡或内容过期 |
| 口述“先记一下今天维护了筛选页，以后写简历再用” | 保存本次来源并更新文字履历，本轮不生成简历 |
| 用户撤回此前确认的结果数字，未提供替代数字 | 保留 ID、旧来源及撤回记录；无可用支持时该字段为 pending，其他职责不降级，也不回退采用旧数字 |
| 附件解析不可用，但用户提供一段实际工作文字 | 先保存可读文字，列出未读附件缺口，不声称读过页数或附件内容 |
| Git 片段在输出首字节前卡住，或输出超过上限 | 截止后终止并回收进程；超长片段标记 truncated，超时不当作空证据 |
| 文件夹中某仓库超时，其他仓库可读 | 部分报告保留成功记录，skipped 写明超时及 errorCode；不声称全部采集成功 |

教学数据见 `examples/`。加入新场景时描述可观察行为，避免只对固定标题或措辞做断言。

## 本地工作台

在独立临时完整副本中运行 `serve_workbench.py --demo`，或使用虚构资料准备普通工作台。

| 场景 | 可观察结果 |
|---|---|
| 修改项目摘要并勾选本人确认 | 检查差异后保存，刷新与重建后值保持一致，项目卡当前字段、来源和历史可回查 |
| 只改一条摘要的展示表达 | 对应字段为 display-only，已有事实来源和其他字段状态保持原样 |
| 另一个 Agent 修改源文件后旧页面保存 | 提示资料基线变化，已有外部修改保留 |
| 新建简历版本 | 正文和依据报告同时另存，原版本保持原样，可下载可读 DOCX |
| 恢复历史前有后续文件变化 | 停止恢复并提示冲突 |
| 只勾选一个项目准备 Agent 材料 | 包含所选项目和相关来源摘录，用户可以复制前检查 |
| 保存有事实映射的旧简历后更正已引用字段，再导出新版 DOCX | 旧正文、报告、DOCX 与来源原文保持不变；影响检查命中对应字段，新版与最新源记录一致，结构校验通过 |

| 用户指出简历漏了多段经历，旧偏好是精简三家公司 | 本轮完整性要求优先，逐段覆盖真实任职并核对项目去向，另存正文与报告，不继续按旧偏好静默删段 |

## 多职业与双格式导出

| 场景 | 可观察结果 |
|---|---|
| 教师只提供年份与任职单位，职称未知 | 工作台保存年份原值与来源，职称留空；图示边界与源日期精度分开 |
| 同一职业履历生成中英文简历 | 两种语言的任职、日期、贡献程度和指标一致，各自正文及依据报告可回溯 |
| 对 `resume.en.md` 不加版式参数直接导出 | 自动采用黑白国际版式；中文仍使用单栏主题版式 |
| 有 Markdown，要求 Word 和 PDF | 从同一 DOCX 转换 PDF，保留旧产物；缺少转换器时明确提示，不声称已生成 PDF |
| PDF 文本可提取但中文显示方框 | 视觉检查发现缺字；用本机字体目录重新转换并复查，不把文字提取成功当作渲染成功 |
| 五职业文档演示重复构建 | 中英文阅读页、Word 下载及来源链接全部可重建，不读取个人 local |

| 职业未在示例中，只有学习和服务记录 | 使用同一 Skill 和事实流程，不注册职业、不要求代码或项目，不补造正式资格 |
| 工作台没有任何项目，选择任职或职业模块准备材料 | 生成待核对材料和依据结构，保留源日期精度，不把草稿当作已完成简历 |
| 只选择一份详细源记录 | 材料区保留所选原文，未选资料不混入，事实与来源均不修改 |
